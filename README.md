# bash-func
Bashをカテゴリ別の関数としてまとめたものです。  
ライブラリを使用するというより、こんな書き方があるのかというサンプルにすることを目的としています。

## 関数コメント規約
`ref` コマンドで定義と一緒に参照できるよう、コメントは関数本体の先頭（`{` / `(` の直後）に記述します。

```bash
func.name() {
  # 関数の概要（1行目）
  # 補足説明（任意・複数行可）
  # opt: x        オプション x の説明（デフォルト: 値）
  # input-stream  入力ストリームの説明
  # param1        第1引数の説明（デフォルト: 値）
  # param2+       第2引数以降（可変長）の説明
  # globals VAR1, VAR2（参照 | 設定）
  # stdout        標準出力に出力する内容
  # returnCd 0:正常 1:エラー内容
  # exitCd 1:処理を終了する場合の終了コード
  # ----
  # 注意事項や使用例などの自由記述
  # usage)
  # func.name -x value arg1 arg2
}
```

- 項目は上記の順に記述し、該当しない項目は省略します。
- `stdout` は標準出力、`returnCd` は終了ステータス（`return`）、`exitCd` はシェル自体の終了（`exit`）を表します。
- 省略可能な引数は `（デフォルト: 値）` で既定値を示します。
- `returnCd` / `exitCd` は `コード:説明` の形式で、コロンの後に空白を入れません。
- 使用例は `# ----` の後に `# usage)` を付けて記述します。

## 入力の扱い
処理対象のデータを引数と入力ストリームのどちらでも受け取れる関数は、Unix コマンド（`cat` や `grep` など）と同じ規則で動作します。

### ファイルを受け取る関数（`file.*` / `yml.*` / `str.evalfile`）
- ファイルが指定された場合はファイルだけを使い、入力ストリームは読みません（消費もしません）。
- ファイルが指定されない場合は入力ストリームを読みます。入力ストリームが端末の場合は読みません。
- `-` を入力ストリームとして扱います（例: `file.stream header.txt -`）。

### 文字列を受け取る関数（`str.stream` を使用する関数）
- 引数の後に入力ストリームを続けて処理します（例: `echo body | str.toUpper header` → `HEADER` / `BODY`）。
- 入力ストリームはパイプかファイルの場合のみ読みます。端末や `/dev/null` は読みません。
- `-n` を先頭に指定すると入力ストリームを読みません。
  `while read` ループの中で呼ぶ場合は、ループの入力を読んでしまうため `-n` を指定してください。
  `ssh` や CI など、入力ストリームが閉じられない環境でも `-n` を指定してください（入力待ちで止まるのを防ぐため）。
- `-` は通常の文字列として扱います。

### 共通
- 検索文字列や文字数などの設定用の引数は、入力ストリームと併用できます。
